DeployOps: rollouts that fail safely

My independent project. It onboards a customer, provisions their database, applies a release and verifies the result, with every step on the record. If a release breaks, the customer’s database stays exactly as it was.

Try it yourself

A small copy of DeployOps running in your browser, with the same five steps and SQL migrations on real SQLite databases. Onboard a customer, deploy a release, then break something. Nothing leaves this page, and a refresh starts over.

Loading the demo. It needs JavaScript; the screenshots on this page show the same screens.

  • 5 steps in every deployment, each one timed and logged
  • 3 database providers behind one interface: SQLite, PostgreSQL and AWS RDS
  • 1 transaction per release, so it lands whole or changes nothing

How it’s built

Python, FastAPI, PostgreSQL, SQLAlchemy and a database-backed worker queue. React and TypeScript for the dashboard. Docker, GitHub Actions, and Terraform for AWS.

How it’s tested

71 automated tests, run in CI against real PostgreSQL, plus a smoke test of the built Docker image. The AWS provider is tested against a simulated AWS and hasn’t run in a real account yet.
